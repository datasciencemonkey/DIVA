UAIG Voice Studio

One call, governed from first word to last.

Every voice turn walks the same path: the caller's browser into a LiveKit room, an agent that listens and speaks, then two governed tools behind Model Context Protocol. One is the Unity AI Gateway, which routes each turn to the model a caller's tier has earned; the other is Lakebase, the read-only store the assistant is allowed to know.

What "governed" guarantees

Four invariants hold on every call, enforced by the tools and the token, never by the conversation.

Tier comes from a governed lookup

The caller's tier is read from Lakebase via read_loyalty_context and drives routing at the gateway. The caller is never told or asked their tier, and it never comes from anything they say.

Every runtime tool is read-only

Both tools the assistant can call (semantic_search and record_lookup) only read. A live call can retrieve knowledge and a caller's own records, but it can never write.

Abstain, never fabricate

When retrieval returns nothing, or the store is degraded, the tool returns empty and the assistant says it doesn't have that information. Grounded answers only; no invented policies, fares, or balances.

Dispatch tokens carry PII-free metadata

The short-TTL LiveKit token embeds only {data_generation_id, customer_id}: identifiers, not identity. Token usage is metered per turn for the Costs pillar, so no caller name ever rides the wire.

Two writes, then read-only forever. One time per world, the studio drafts synthetic documents, customers, and records through the gateway and embeds them into Lakebase (schema ug) with FMAPI. After that, every path a live call touches (routing, retrieval, tier lookup) only reads.
