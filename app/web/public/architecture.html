UG Voice Studio
Studio Architecture

One call, governed from first word to last.

Every voice turn walks the same path: the caller's browser into a LiveKit room, then an agent that listens and speaks. The agent picks its model from the caller's tier, in the app, and reaches it through the Unity Gateway, Databricks' governed access to model serving. Each turn, AI Decide works out, outside the conversational model, whether the caller wants the spooky voice. The assistant's knowledge comes from Lakebase, the read-only store it is allowed to know — retrieval is Lakebase Search (lakebase_vector ANN).

Built on Agent Bricks
  • Databricks Apps one container for the web tier and the agent
  • Unity Gateway governed access to model serving
  • Lakebase the read-only store and its search index
The agent itself is a LiveKit Agents worker.

  • Control governance, voice mode
  • Context retrieval

  1. Generate a world. Name a fictional company, a role and a system prompt. The generator drafts documents, customers and records through Unity Gateway, embeds them, and writes them to Lakebase in one transaction under a fresh data_generation_id. Indexes are Lakebase Search: lakebase_ann (cosine ANN via lakebase_vector) and lakebase_bm25 (BM25 via lakebase_text).
  2. Load the studio. The browser fetches the studio from the web tier and lists the worlds stored in Lakebase.
  3. Start a call. The web tier mints a short-lived LiveKit token (GET /api/token) that carries data_generation_id and customer_id, and dispatches the agent into a fresh room.
  4. Join the room. The browser connects to LiveKit Cloud over WebRTC with that token.
  5. Dispatch the agent. LiveKit hands the job to the agent worker, which stays registered as ug-agent over a WebSocket.
  6. Bind and route. The agent worker looks up the caller's tier in Lakebase (never from speech), and route_for(tier) picks the model from the UG_MODEL_* map. That choice is app logic: Unity Gateway only serves the model it names. The model never sees the tier.
  7. Talk. Deepgram STT (nova-3) turns speech into text and the routed LLM answers through the gateway's Responses API. A TTS voice speaks the reply: Deepgram (aura-2) in the standard voice, ElevenLabs (eleven_v3_conversational, with inline expressive tags) once the call is in Halloween mode, or a darker Deepgram voice if ElevenLabs isn't configured. Which voice applies is decided on every caller turn, outside the LLM: Databricks AI Decide classifies what the caller wants (enter, exit or none) and a deterministic policy applies it, with at most one change per turn and an explicit exit always winning.
  8. Ground. semantic_search is Lakebase Search ANN (ORDER BY embedding <=> $q on the lakebase_ann index), with the question embedded through the gateway first; record_lookup is plain SQL and only returns the caller's own records. Both tools are scoped to the bound dataset.
  9. Show. PII-free evidence (routing decision, retrieval hits, token usage, voice mode) streams to the UI over the LiveKit data channel, and the studio renders it as the Choice / Control / Context / Costs pillars. The voice mode shows on the Control pillar as a live “Voice mode · AI Decide” row.
  10. Trace. The spans flush over OTLP into a Unity Catalog table, where they read as MLflow traces. Each voice-mode change adds a ug.ai_decide span, and the root span carries ug.voice_mode, ug.voice_mode_transitions, ug.voice_degraded, ug.decide_engine and ug.expressive_tags.

What "governed" guarantees

Six guarantees hold on every call, enforced by code, the tools and the token, never by the conversation.

Tier comes from a governed lookup

The caller's tier is read from Lakebase via read_loyalty_context and picks the model inside the agent, with route_for(tier) over the UG_MODEL_* map. The gateway only serves the model it is asked for. The caller is never told or asked their tier, and it never comes from anything they say.

Every runtime tool is read-only

Both tools the assistant can call (semantic_search and record_lookup) only read. Retrieval is Lakebase Search ANN (lakebase_vector), not pgvector HNSW. A live call can retrieve knowledge and a caller's own records, but it can never write.

Abstain, never fabricate

When retrieval returns nothing, or the store is degraded, the tool returns empty and the assistant says it doesn't have that information. Grounded answers only; no invented policies, fares, or balances.

Dispatch tokens carry PII-free metadata

The short-TTL LiveKit token's metadata embeds only {data_generation_id, customer_id}: identifiers, not identity. The one personal detail in the token is the name the caller gives for the greeting, carried as its sanitized name claim. Token usage is metered per turn for the Costs pillar.

AI Decide picks the voice, never the treatment

Voice mode is decided every turn outside the conversational LLM, and it never changes the routed model, the directives or escalation (G9). AI Decide sees only the caller's words, the agent's previous line (its last 200 characters) and the current mode: never the tier, name, customer id, dataset prompt or retrieved documents (G10). The one indirect route is that previous line, which can echo the caller's first name from the greeting. A deterministic policy makes at most one change per turn, and an explicit exit is always honored (G12).

The persona can't break the rules

The spooky persona sits before the governance block, and facts are spoken exactly as the tools return them (G11). Expressive tags such as [whispers] are performed by the voice, never read aloud and never shown in the transcript (G13). Every mode change is a ug.ai_decide span and a live row on the Control pillar.

Two writes, then read-only forever. One time per world, the studio drafts synthetic documents, customers, and records through the gateway and embeds them into Lakebase (schema ug) with a Unity Gateway embedding model. After that, every path a live call touches (routing, retrieval, tier lookup) only reads, and the voice mode is per-call state that is never written to Lakebase.
